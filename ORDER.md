# ORDER — repository order rules

**Binding** rules. They are not recommendations: a change that contradicts them is not accepted. To change a rule, change
**this document first**, in its own commit, and the rest of the change follows. Spanish version: [ORDEN.md](ORDEN.md).
Mechanical check: `python scripts/audit/check_order.py` (and `pytest tests/test_order.py`).

## 1. One source per subject

| Subject | Single source | Everything else |
|---|---|---|
| Public front page | [README.md](README.md) / [README.en.md](README.en.md) | links, never copies tables |
| Contribution rules | [CONTRIBUTING.md](CONTRIBUTING.md) / [CONTRIBUTING.en.md](CONTRIBUTING.en.md) | — |
| Repository order | this document ([ORDEN.md](ORDEN.md) / [ORDER.md](ORDER.md)) | — |
| Minimal context for agents | [knowledge/CURRENT.md](knowledge/CURRENT.md) (≤ ~150 lines) | — |
| Standing conclusions and limits | [docs/STATE.md](docs/STATE.md) | — |
| Open, blocked and closed tasks | [docs/PENDIENTES.md](docs/PENDIENTES.md) | — |
| Research chronology | [knowledge/PROGRESS.md](knowledge/PROGRESS.md) | — |
| Report index by subsystem | [docs/INDEX.md](docs/INDEX.md) | — |
| Canonical reports of a work line | `docs/capture/` | `reports/` only while the case is live |
| Reproducible evidence | `analysis/` | — |
| Verifiers | `tests/` | — |
| Replication guide (EN/ES) | `wiki/` | `site/` is only the dashboard |
| Published dashboard | `site/` (data generated by `scripts/build_pages_status.py`) | — |
| Target feature list | [FUNCIONES.md](FUNCIONES.md) | — |

Duplicating content is forbidden: write it in its single source and **link** from everywhere else.

## 2. Where a new file goes

| Kind | Path | Name |
|---|---|---|
| Report of a session or phase | `docs/capture/` | `<prefix>-<slug>.md` |
| Working report from an agent or subagent, case still open | `reports/` | `<case>-<topic>-YYYYMMDD.md` |
| Evidence (dumps, JSON, one-off scripts) | `analysis/<case>/` | free, lowercase |
| Analysis or camera script | `scripts/<area>/` | `snake_case.py` |
| GUI / CFW lane script | `scripts/gui/` | `snake_case.py` |
| Verifier for a report | `tests/` | `test_<prefix>_<topic>.py` |
| Wiki page | `wiki/` | `<n>-Titulo.md` **and** `en-<n>-Title.md` |
| Derived document | `docs/CORRECTIONS.md`, `docs/OPEN-QUESTIONS.md`, `docs/INDEX.md` (generated section), `knowledge/audit/*.json` | scripts only |

Prefixes in use: `s<N>` session, `e<NN>` static phase, `e25-`/`e26-` shutter and recovery, `e26-r<NN>` recovery report,
`g<NNN>` GUI lane, `p<NN>` physical plan, `og-` open gate, `usb-carga-` USB charging, `cam-` camera incidents.

## 3. Names

- Lowercase, hyphens or `snake_case` as per the table above; no spaces, no accents. Legacy files with capitals stay to avoid breaking links; new ones are lowercase.
- One ID, one file. IDs are never renamed or reused: a new ID is the next free one for its prefix.
- If two reports cover the same thing, the second **corrects** the first with an explicit link; analysis is never duplicated.
- Date suffixes are forbidden in `docs/capture/` (the date goes inside the document) and mandatory in `reports/`.

## 4. Internal order of a document

1. `# Title` with prefix and ID when it exists.
2. Metadata header: date, state, sources.
3. Body: verified facts → inferences → what is missing.
4. A **Limits** section (what was not measured and what the report does not prove).
5. Links to evidence and related reports.

Every `.md` tells the **current** truth; history lives in Git. Old versions, “it used to say” blocks and sections that no longer
hold are forbidden.

## 5. Normalised states

- Evidence for each claim: `VERIFICADO`, `INFERENCIA`, `NO_VERIFICADO`.
- Tasks: `ABIERTO`, `PARCIAL`, `BLOQUEADO`, `CERRADO`, `CERRADO CON LÍMITE`, `DESCARTADO`.
- Any other state in `docs/PENDIENTES.md` is an order failure.

## 6. Commit and publication order

- One commit per phase or fix, Conventional Commits (`type(scope): summary`), with `docs/PENDIENTES.md` updated **in the same commit**.
- Push to `origin/main` when each phase closes, with the `nicolvus` account.
- Sony firmware, Sony binaries, camera `*.bin`/`*.elf`, RAW files and personal data are never committed.

## 7. Wiki: mandatory pairs

- Every `wiki/<n>-Titulo.md` has its twin `wiki/en-<n>-Title.md` with the **same number and the same structure**.
- Content changes go to both in the same commit; if only one can be done, the other says so.
- A new page enters both blocks of `wiki/_Sidebar.md` in the same commit.
- Wiki links are written as full URLs `https://github.com/nicolvus/a6000-fw-decomp/wiki/<slug>`; code links as
  `https://github.com/nicolvus/a6000-fw-decomp/blob/main/<path>`.

## 8. Site

- `site/status.json` and `site/badge-*.json` are **generated**: regenerate them with `scripts/build_pages_status.py`, never edit by hand.
- `site/index.html`, `site/app.js`, `site/styles.css` and `site/progress/index.html` are hand-written; their data must match
  `docs/STATE.md` and `README.md`.
- Site and wiki publish themselves (`pages.yml`, `wiki.yml`); nobody publishes by hand.

## 9. Absolute prohibitions

1. Links to `releases/tag/...` while the repository has no releases.
2. Citing a firmware version without its build, report or closure criterion.
3. Repeating the target-feature table, the version table or the global state in more than one source.
4. Renaming, moving or deleting a linked file without updating every link in the same commit.
5. Leaving in a document claims that another document already corrected.
6. Editing a generated derivative by hand.
7. Committing `.md` changes without running `knowledge-maintenance` and `check_order.py`.

## 10. Check before every commit

```sh
python scripts/audit/check_order.py     # this document's rules, mechanically
python -m pytest tests/knowledge tests/test_order.py -q
CI=1 python -m pytest tests -q          # no firmware
```

## 11. Current rules: fetched from `a6000-handoff-context`

**New rules about repository order** are published in the private repository
[`nicolvus/a6000-handoff-context`](https://github.com/nicolvus/a6000-handoff-context) before they reach
this document. At the start of every session, and always before deciding anything about repository order:

```sh
bash scripts/agent/sync_rules.sh   # fetches the current rules and lists what differs from the local copy
```

- **GitHub wins**: whatever it brings is applied in the session and, if the local copy fell behind, it is
  updated in the same commit.
- An older snapshot never deletes a local rule: if GitHub does not have a rule yet, it stays in force.
- To change a rule: the handoff repository first, then this document, and the rest of the change behind it,
  as with any order rule.
